Overview

This site lets you turn an S3 Inventory report into a queryable index and then explore it by prefix — object counts, sizes, and per-tier cost estimates, all in milliseconds.

There are three pages: Dashboard for an at-a-glance overview, Inventories for loading and managing builds, and Browse for exploring a loaded inventory.

Pages

Dashboard

The landing page. Counters at the top show how many inventories the server knows about and how many are loaded, not loaded, or in an error state. A list underneath shows every inventory. Read-only — use it to spot which inventories are ready to query.

Inventories

One section per S3 inventory configuration, with one row per published run inside. Runs are listed newest-first so the most recent snapshot is at the top of each section. This is the only page where you Load, Retry, Unload, or Cancel a build. Each row updates live while a job is in flight — no refresh needed. Different runs of the same inventory configuration are independent — loading one doesn't affect the others, so you can keep multiple snapshots in memory at once and compare them on Browse.

Browse

A directory-style explorer over one loaded inventory. Pick an inventory in the dropdown, type a prefix or click into children, see aggregated object count, size, and per-tier cost. The address bar always reflects the view — copy the URL to share or bookmark it.

Workflows

Load an inventory

  1. Open Inventories.
  2. Find the row. Click Load (or Retry if it's in an error state).
  3. The chip flips to Loading… and a spinner shows the current build stage: Preparing → Initializing → Downloading & parsing → Building index → Done. A progress bar and ETA appear during downloading.
  4. When the build finishes, the chip becomes Loaded. The node count fills in.
  5. Open Browse to query it.

You can navigate away while the build is running — closing the page does not cancel it. Come back to Inventories any time and the row reflects the latest state.

Browse a prefix tree

  1. Open Browse and pick a loaded inventory.
  2. Empty prefix = the bucket root. Type a prefix and press Enter to jump straight there.
  3. Click a child prefix (📁) to drill in. The breadcrumbs at the top navigate up.
  4. Click a column header — Segment / Objects / Size / Est. Cost — to sort the children.
  5. Expand the Storage tier breakdown panel to see per-storage-class counts and the monthly cost estimate.

Recover from errors

  • Build failed. Hover the small "Error" label under the chip for the message, then click Retry.
  • Build stuck. If the ETA stops moving, click Cancel, then Retry.
  • Row shows "interrupted by server restart". A build was running when the server stopped. Click Retry.
  • Wrong inventory loaded. Click Unload to drop it from memory and disk, then click Load on the run you actually want.

Cost model

All cost figures come from a single us-east-1 price table. Numbers are estimates — the goal is to make tier and run comparisons meaningful, not to reproduce your bill to the cent.

Monthly storage

For each tier present at a prefix:

  • Base: bytes ÷ GB × $/GB-month at that tier's rate.
  • Standard-IA, One Zone-IA, and Glacier Instant Retrieval bill every object as if it were at least 128 KiB. Smaller objects pay the difference.
  • Glacier and Deep Archive add per-object metadata overhead (32 KiB at the Glacier rate plus 8 KiB at the Standard rate).
  • Monitored Intelligent-Tiering tiers add the per-object monitoring & automation fee.

PUT API cost (Compare only)

The Compare page surfaces a one-time PUT API charge alongside monthly storage, so you can see what it cost to land the run's objects in S3 in the first place: objectCount ÷ 1000 × $0.005. PUTs/COPYs/POSTs are billed at $0.005 per 1,000 requests in us-east-1.

Storage tiers

Standard, Standard-IA, One Zone-IA, Glacier Instant Retrieval, Glacier Flexible Retrieval, and Deep Archive each have a fixed monthly rate. Intelligent-Tiering objects are bucketed by access tier — Frequent, Infrequent, Archive Instant, Archive, and Deep Archive — and the monitored tiers add the per-object monitoring fee. Reduced Redundancy is deprecated by AWS but still costed when present.

Intelligent-Tiering Frequent (< 128 KiB). AWS does not monitor or auto-tier Intelligent-Tiering objects smaller than 128 KiB — see S3 Intelligent-Tiering. These objects are split into their own bucket at ingest so the storage cost stays at the Frequent rate and they don't accrue the monitoring fee.

State chips

Every inventory row has a colored chip showing its current state.

Chip Meaning Available action
{{stateLabel "not_loaded"}} Discovered in S3, never built. Load
{{stateLabel "loading"}} A build is running. Stage and ETA appear below the chip. Cancel
{{stateLabel "loaded"}} The index is ready; the inventory shows up on Browse. Unload
{{stateLabel "error"}} Last build failed or was interrupted. Hover the small Error label for the message. Retry

Action buttons

Only the buttons that are valid in the current state appear on each row.

Button Shown when What it does
Load State is Not loaded Kicks off a fresh build of the index.
Retry State is Error Same as Load — wipes any partial files and starts a new build.
Unload State is Loaded Releases the inventory from memory and removes its on-disk cache. The row returns to Not loaded.
Cancel A build is running Stops the in-flight build. The row flips to Error and you can click Retry.

Progress & ETA

While an inventory is loading, the row shows the current build stage, a progress bar, and an estimated time remaining. Updates come through automatically — leave the page open and the bar moves, or come back later and see the latest state. The build runs on the server, not in your browser, so closing the tab doesn't stop it.

The ETA is a simple linear projection: it watches how long the work has taken so far and assumes the rest will take roughly the same per unit. It's noisy at the very start and settles to within ~10% once a few chunks have been ingested.

Sharing URLs

Browse is fully reflected in the address bar — every drill-down, sort header, and page change updates the URL. Copy the address at any point and send it to a teammate: opening that link lands them in the exact same view (assuming the inventory is also loaded on their session).

Browser back and forward work as you'd expect: each click into a child prefix is a history entry. The Inventory dropdown and Prefix input always reflect the URL you're on, so navigating back to the root resets them too.

Dark mode

The sun / moon button in the top-right of every page toggles dark mode. Your choice is stored locally in this browser and applied before the first paint, so there's no light-mode flash when you reload. If you've never set a preference, the site follows your OS-level setting.

Restarts & saved state

The server remembers which inventories you've loaded across restarts. When the server comes back up:

  • Inventories that were Loaded are reopened from the cache — no rebuild, ready to query.
  • Inventories that were mid-build flip to Error with the message "interrupted by server restart". Builds can't safely resume from a partial cache, so the recovery is honest about it and asks you to Retry.
  • Inventories that were idle (Not loaded, Unloaded) stay in the same state.

Keyboard

  • Tab walks every page in reading order.
  • Enter or Space activates any button.
  • Enter in the Prefix input on Browse jumps directly to that prefix.
  • Child prefix links on Browse are real anchors — middle-click or Ctrl+click opens them in a new tab.

Troubleshooting

A build is stuck and the ETA isn't moving.
Click Cancel. The build stops at the next safe checkpoint and the row flips to Error. Then click Retry.
Row shows "interrupted by server restart".
Expected — a build was running when the server stopped, and partial builds can't safely resume. Click Retry to rerun cleanly.
The Inventories list is empty.
{{if .HasDiscovery}} No S3 inventory configurations were found at the configured location. Make sure at least one inventory has published a completed run. {{else}} S3 discovery isn't configured for this server. The operator needs to start the server pointing at a source location for inventories to appear. {{end}}
Browse dropdown says "Select a loaded inventory" but I just loaded one.
The dropdown only lists inventories currently in the Loaded state. If yours is Loading…, wait for the build to finish. If it's Not loaded or Error, click Load / Retry on the Inventories page first.
Pages feel slow after a lot of navigation.
If clicks stop responding for a while, hard-reload the page (Cmd/Ctrl+Shift+R) to drop any stale background connections. Things should be snappy again.
Browse doesn't show a storage tier breakdown for an inventory.
Some S3 inventory configurations don't include the storage-class column. Without that column the per-tier breakdown and cost estimate can't be computed — only total counts and bytes are shown.

Glossary

Inventory
An S3 Inventory configuration — a periodic report listing every object in a source bucket.
Run
One snapshot produced by an inventory configuration. The site uses only the latest run per inventory.
Index
The compact, queryable form built from an inventory. Lets Browse answer prefix questions in milliseconds.
Prefix
A path inside the source bucket — e.g. data/2024/. Browse navigates the prefix tree.
Tier
The S3 storage class — Standard, Standard-IA, Glacier Instant, and so on.
Cost estimate
Monthly $ figure computed from the per-tier object counts and sizes using S3's US-East-1 prices.
