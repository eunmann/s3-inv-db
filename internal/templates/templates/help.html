# Overview

s3-inv-db turns an S3 Inventory report into a queryable, memory-mapped index. The HTTP server discovers inventories under an s3:// source, builds an index per inventory in the background, and exposes prefix-level counts, sizes, and storage-tier cost estimates via an HTMX-driven UI plus a JSON API.

Three pages — Dashboard, Inventories, Browse — and a tiny REST surface. Builds run async; the UI shows live progress over Server-Sent Events. State persists to SQLite so restarts don't lose work.

# Pages

# Dashboard GET /

Top-level counters (total / loaded / not loaded / error) plus a list of every inventory the server knows about. Read-only. Discovery-aware: when --s3-source is set, the list reflects S3-discovered inventories merged with current load state.

# Inventories GET /inventories

One row per discovered S3 inventory configuration. The only page where you can Load, Reload, Retry, Unload, or Cancel a build. Rows update live via SSE while a job is in flight.

# Browse GET /browse?inventory_id=&prefix=

Directory-style explorer over one loaded inventory. Pick an inventory, type a prefix or click into children, see aggregated object count + size + per-tier cost. URLs are shareable — every column-sort, page, and prefix is round-trippable.

# Workflows

# Load an inventory

  1. Open Inventories.
  2. Find the row. Click Load (or Reload / Retry depending on state).
  3. State chip flips to Loading…. Server returns 202 immediately; the build keeps running in the background.
  4. SSE pushes updates: stage label (Preparing → Initializing → Downloading & parsing → Building index → Done) plus progress bar and ETA during the downloading stage.
  5. When done, the chip becomes Loaded. Node count and tier-data flag populate.

Closing the tab doesn't stop the build. Reopen Inventories to see current state.

# Browse a prefix tree

  1. Open Browse. Choose a loaded inventory in the dropdown.
  2. Empty prefix = bucket root. Type a prefix and press Enter to jump.
  3. Click a child prefix (📁) to drill in. Breadcrumbs at the top navigate up.
  4. Sort the children table by Segment / Objects / Size / Est. Cost — click the header.
  5. Each column shows current aggregate. Tier breakdown is in the collapsible “Storage tier breakdown” panel.

# Recover from errors

  • Build failed (chip = Error) → hover the small "Error" subtitle for the message → click Retry.
  • Build stuck (no ETA progress for >30s, network frozen) → click Cancel, then Retry.
  • Server restarted mid-build → row shows Error: "interrupted by server restart". Click Retry.
  • Wrong cache → click Unload, delete $CACHE_DIR/<src>/<id>/ on the host, click Load.

# Progress & ETA

Each Inventories page opens a single SSE connection (GET /api/jobs/stream). The server emits one frame per job-state transition, named row-<composite-id>; htmx re-fetches the row whenever its frame arrives.

Pipeline stages, in order: preparing → initializing → downloading → building → done. Quantitative progress (the chunk counter + ETA) only emits during downloading.

ETA is a linear projection from elapsed time: 

remaining = elapsed × (total − done) / done

The number is jittery for the first 1-2 chunks and settles within ~10% by the time a quarter of the manifest is ingested.

# SSE stream

GET /api/jobs/stream emits two frames per job state change — one keyed by job ID for debug consumers, one keyed by inventory ID for the row swap mechanism. A : ping heartbeat fires every 15s so departed clients are detected quickly. 

event: job-cbae234ba939f5d005e161e3
data: {"ID":"cbae234ba939f5d005e161e3","InventoryID":"my-bucket/daily","Kind":"build","State":"running","Stage":"downloading","BytesDone":3,"BytesTotal":10,...}

event: row-my-bucket/daily
data: {...same...}

: ping

Curl test: curl -N http://localhost:8080/api/jobs/stream.

# Persistence

The server writes a SQLite file at $CACHE_DIR/state.db (override with --state-db). Schema:

  • inventories — one row per registered inventory, mirrored from the in-memory Manager.
  • jobs — one row per build / load job, with FK ON DELETE CASCADE.

On startup:

  • Jobs in queued or running are stamped aborted.
  • Inventories in loading flip to error with reason "interrupted by server restart".
  • Inventories in loaded are re-opened from their on-disk index — no rebuild.
  • Inventories whose Open fails flip to error so the UI surfaces a Retry.

Pragmas: journal_mode=WAL, synchronous=NORMAL, foreign_keys=ON, busy_timeout=5000.

# Configuration

All flags accept an env-var alternative. Run with -h for the canonical list; the table below is a cheat sheet.

Flag Env var Purpose
--addr :8080 — HTTP listen address.
--s3-source s3://… S3INV_SOURCE Discovery root. Without it, /inventories is empty.
--cache-dir /var/cache/s3inv S3INV_CACHE_DIR Where built indexes + state.db live.
--state-db /path/state.db S3INV_STATE_DB Override the default $CACHE_DIR/state.db.
--price-table path.json — Override US-East-1 prices for cost estimates.
--verbose — Debug logging.
--pretty-logs — Human-friendly console output (default is JSON).

# Keyboard

  • Tab walks every page in reading order.
  • Enter / Space activates any button.
  • Enter in the Prefix input on Browse jumps directly to that prefix.
  • Browse child links are real <a> tags — middle-click or Ctrl+click opens in a new tab.

# Troubleshooting

A build is stuck and the ETA isn't moving.
Click Cancel. The pipeline winds down at its next safe checkpoint and the row flips to Error. Then click Retry. If the same inventory consistently hangs in the same stage, check the server logs — the manifest may point at unreachable objects.
Row shows "interrupted by server restart".
Expected — mid-flight builds can't safely resume. The partial cache directory is invalid. Click Retry to rerun cleanly. Inventories that were fully loaded before the restart come back as Loaded automatically.
The Inventories list is empty.
{{if .HasDiscovery}} The server is configured with {{.S3Source}} but no inventory configurations were found there. Make sure your S3 Inventory configuration is publishing reports under that prefix and at least one run has completed. {{else}} Discovery is disabled. Start the server with --s3-source s3://bucket/inventory-prefix/ to populate the list. {{end}}
Browse dropdown shows "Select a loaded inventory" but I just loaded one.
The dropdown only lists inventories currently in the Loaded state. If yours is Loading…, wait for the build. If it's Unloaded or Error, click Reload / Retry first.
I want to free disk space.
Click Unload, then rm -rf $CACHE_DIR/<src>/<id>/ on the host. The row returns to Not loaded on the next refresh; click Load to rebuild.
My curl gets 403 on a POST.
CSRF middleware rejects mutating requests whose Origin or Referer doesn't match the server. Use the JSON API from same-origin scripts, or set an Origin header on curl that matches the host.
Page hangs after several navigations.
Chrome's per-origin connection limit is 6. Stale SSE streams used to eat them; the server's 15s heartbeat detects gone clients quickly now. If you still see hangs, hard-reload (Cmd/Ctrl+Shift+R) to drop any lingering connections.

# Glossary

Inventory
One S3 Inventory configuration — a manifest describing every object in a source bucket at a point in time.
Run
One snapshot produced by an inventory configuration. The server uses only the latest run per inventory.
Index
The mmap-backed on-disk artifact built from an inventory. Enables O(1) prefix lookups and fast subtree aggregation.
Composite ID
The <src-bucket>/<inv-id> pair the server uses internally — same string that appears in API paths and SSE event names.
Prefix
A path inside the source bucket (e.g. data/2024/). Browse navigates the prefix tree.
Tier
The S3 storage class — Standard, Standard-IA, Glacier Instant, etc.
Cost estimate
Monthly $ figure from tier breakdown × price table. Defaults to US-East-1; override with --price-table.
SSE
Server-Sent Events — one-way push channel from server to browser. Used by /api/jobs/stream.
