Overview

AWS writes an S3 Inventory report for a bucket every day or week: a list of every object with its size and storage class. This site turns one report (a run) into a small local index, then answers questions about the bucket in milliseconds: how big each folder (prefix) is, how many objects it holds, what it costs per month, and how all of that changed since an earlier run.

To get started:

  1. On the Dashboard or Inventories, click Load on a bucket's latest run. Building the index takes seconds to minutes.
  2. Click Browse to see where the space is, largest folders first.
  3. Load a second run of the same inventory and click Compare with previous to see what grew or shrank.

The index holds totals per prefix, not individual objects, so you can't look up a single file here.

Pages

Dashboard

One card per inventory, bucket name first, showing its latest loaded run: objects, total size and estimated monthly cost, plus the change since the previous loaded run when there is one. From a card you can Browse the run, Compare with previous, or Load the latest run if nothing is loaded yet (or a newer run has arrived). Below the cards, a short status section shows running and failed builds (each failure links to its run), whether auto-load is on, and how much of the index disk is used.

Inventories

One card per inventory with its runs, newest first. The latest run and any run that is loaded, building or failed are always shown; older runs fold away under Show N older runs. A loaded run shows its objects, size and monthly cost. This is where you load, cancel, retry, pin and unload runs. Rows update by themselves while a build runs. View details opens a side panel with the run's totals, storage-class breakdown, where its report came from, and the build's step-by-step timeline. Refresh checks S3 for new runs right away instead of waiting for the next scheduled check.

Browse

Explore one loaded run as a folder tree. The top shows the current prefix's size, objects and monthly cost, with the storage-class breakdown and each class's share of the size. Below, its children are listed largest first, each with its share of the parent. Click a child to go into it; the breadcrumbs take you back up. Click a column header to sort by name, size, objects or cost. Type a prefix to jump straight to it. "Queried in …" shows how long the answer took.

Compare

Put two loaded runs of the same inventory side by side. The top shows how much the size, the monthly cost and the object count changed; children are listed by the size of their change. Red means grew, green means shrank; Added and Removed mark prefixes that exist in only one run. Pick one run and the other side is filled in with its neighbouring loaded run. Unchanged prefixes are hidden until you click Show unchanged.

Workflows

Load a run

  1. Click Load on a run (Dashboard or Inventories). If another build is running it waits as Queued.
  2. The row shows the stage, its percent and the time left, over a bar with one segment per stage. See Progress & time left.
  3. When it finishes the chip turns Loaded and the row shows the run's objects, size and cost.

The build runs on the server: you can leave the page or close the tab, and the row shows the latest state when you come back.

Find where the space is

  1. Click Browse on a loaded run.
  2. The largest child is at the top; the % of parent column shows how much of the total it holds.
  3. Click into it and repeat until you reach the prefixes worth acting on. The storage-class breakdown at each level shows whether the space is in cheap or expensive classes.

See what changed

  1. Load two runs of the same inventory, for example today's and last week's.
  2. Click Compare with previous on the newer run, or pick both runs on the Compare page.
  3. The biggest changes are at the top. Click a prefix to see which of its children changed.

Recover from a failed build

  • A failed run shows a one-line reason in red. View details has the full error under Technical details.
  • Fix the cause if it's on the S3 side (a missing report file, missing permissions), then click Retry.
  • A build that seems stuck can be stopped with Cancel; the run goes back to Not loaded and you can load it again.
  • If an action can't be done (for example the run changed state in the meantime), a message appears at the top of the page saying why.

Cost estimates

Monthly costs are estimates of storage only, from one price table (us-east-1). They are meant to make prefixes, storage classes and runs comparable, not to reproduce your bill. For each storage class present at a prefix:

  • Size × that class's price per GB-month.
  • Standard-IA, One Zone-IA and Glacier Instant Retrieval bill each object as at least 128 KiB.
  • Glacier Flexible Retrieval and Deep Archive add per-object metadata (32 KiB at the Glacier rate plus 8 KiB at the Standard rate).
  • Intelligent-Tiering adds its per-object monitoring fee for the tiers it monitors. Objects under 128 KiB aren't monitored or moved by AWS, so they are counted separately at the Frequent rate without the fee.

Requests, retrievals and data transfer are not included. If an inventory doesn't report storage classes, only sizes and object counts are shown.

Action buttons

A run only shows the actions that make sense in its current state.

Load
Builds the run's index. A run you load by hand is also pinned.
Cancel
Stops a queued or running build. The run goes back to Not loaded.
Retry
Starts a failed build again from scratch.
Browse
Opens the run on the Browse page at the bucket root.
Compare with previous
Compares the run with the previous loaded run of the same inventory. When there is none, Compare opens the Compare page with this run picked.
Pin / Unpin
A pinned run is never removed automatically to free disk space or by auto-load's retention. See Auto-load, pins & disk.
Unload
Deletes the run's index from this server after asking you to confirm. Nothing in S3 is touched; loading it again rebuilds the index.

Progress & time left

A build goes through these stages: Downloading & parsing the report, Merging (large inventories only), Building index, and Finalizing, which has its own steps such as writing the hash table and checksumming the files. The row shows the current stage, its percent and the time left; the bar has one segment per stage and only moves forward.

The time left is estimated from the current stage's pace so far and smoothed so it doesn't jump. A stage that can't measure its progress yet shows a moving segment instead of a percent. View details shows each stage's duration once the build is done.

Auto-load, pins & disk

When the server runs with auto-load on, each inventory card on Inventories has Auto-load latest run and Keep last N runs. With auto-load ticked, the server loads each new run on its own and keeps the newest N runs loaded. When auto-load is off on the server, the page says so and these settings are hidden. Settings fixed by the server's configuration file are shown but can't be changed here.

The server has a disk limit for indexes. To make room for a new run it first removes runs past an inventory's retention, then the runs used least recently. It never removes a pinned run or one that is being read. A run you unload by hand is skipped by auto-load until a newer run appears.

Links & history

Browse and Compare keep the address bar in step with what you see: the run, the prefix, the sort and the page. Copy the address to share a view; anyone with access to this server sees the same view as long as the run is still loaded. Every link opens in a new tab with a middle-click, and the browser's Back and Forward buttons step through the prefixes you visited. Opening a run's details on Inventories adds #run=… to the address, so a link can open that panel directly.

Dark mode

The sun/moon button at the top right switches between light and dark. Your choice is remembered in this browser; until you choose, the site follows your system setting.

Restarts & saved state

  • Loaded runs stay loaded across server restarts: they reopen from disk without a rebuild.
  • A build running when the server stops shows Interrupted by a server restart. Builds can't safely resume halfway, so load the run again.
  • Pins, auto-load settings and recent build history are kept.

Keyboard

  • Tab moves through every link and button in reading order; Enter or Space activates it.
  • Enter in the Prefix box on Browse or Compare jumps to that prefix.
  • Esc closes the run details panel.
  • A screen reader announces when a build finishes, fails or is cancelled.

Troubleshooting

A build failed: "An inventory data file is missing from S3".
A file the run's report lists is gone from S3, usually because the report was deleted or expired. Load a newer run instead.
A build failed: "Access denied".
The server can't read the inventory files. Ask whoever runs it to check its S3 permissions, then click Retry.
A build failed: "Not enough room in the index disk budget".
The index disk is full of runs that can't be removed (pinned or in use). Unpin or unload runs you no longer need, then load again. Whoever runs the server can also raise its disk limit.
A build looks stuck.
Large inventories spend minutes in some steps; View details shows which step is running. If nothing moves for a long time, click Cancel and load it again.
A run shows "Interrupted by a server restart".
The server stopped during the build. Load the run again.
The Inventories page lists nothing.
No inventory report has been published at the location the server watches yet. AWS writes the first report within 48 hours of setting up an inventory. Click Refresh to check again.
A run isn't listed on Browse or Compare.
Only loaded runs are listed. Load it on Inventories first; Compare also needs two loaded runs of the same inventory.
"Live updates are disconnected".
The page lost its connection to the server and is reconnecting by itself. Running builds still refresh every few seconds until it's back.
No storage-class breakdown or cost.
The inventory doesn't include the storage class field. Add it to the inventory's configuration in AWS; new runs will then show the breakdown and cost.

Glossary

Inventory
An S3 Inventory configuration on a bucket: AWS writes a report of every object in it on a schedule.
Run
One of those reports, a snapshot of the bucket on one day. You can load several runs of the same inventory and compare them.
Index
The compact, queryable form of a run this server builds when you load it.
Prefix
A folder-like path inside the bucket, e.g. data/2024/. Its totals include everything below it.
Storage class
Where AWS keeps an object and how it's priced: Standard, Standard-IA, Glacier, Intelligent-Tiering and so on.
Pinned
A loaded run that is never removed automatically.
