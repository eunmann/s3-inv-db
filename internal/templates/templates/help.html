Help v1

Everything you can do here.

s3-inv-db turns an S3 Inventory report into a queryable, mmap-backed index — prefix counts, sizes, and storage-class breakdowns in milliseconds. This is the map of the UI.

§ 01 — Quick start

Three clicks to first query.

  1. 01

    Find an inventory.

    Open Inventories. Each row is one S3 inventory configuration discovered under your --s3-source.

  2. 02

    Click Load.

    The build runs in the background. The row turns blue, shows the current pipeline stage and an ETA. Navigate away and come back — the row keeps updating live.

  3. 03

    Open Browse.

    Pick the loaded inventory. Drill into child prefixes. See per-prefix object counts, sizes, and monthly cost estimates by storage class. Try it →

§ 02 — Pages

Three pages, one job each.

Dashboard
Counters for total / loaded / not-loaded / error, plus a list of everything the server currently knows. Read-only — use it to spot which inventories are ready to query.
Inventories
One row per discovered S3 inventory. The only place you Load, Unload, Retry, or Cancel an in-flight build.
Browse
Directory-style explorer over a loaded inventory. URLs are shareable — the entire view is reproducible from ?inventory_id=&prefix=&sort=&dir=&page=.
§ 03 — Workflow

Loading an inventory.

Loading turns a remote S3 inventory report into a local, mmap-backed index. It's asynchronous — the build runs in the background and the row updates live over a single Server-Sent Events stream.

  1. Find the inventory row on Inventories.
  2. Click Load — or Reload / Retry, depending on current state.
  3. The state chip flips to Loading… and a spinner plus stage label appears: Preparing → Initializing → Downloading & parsing → Building index → Done. A progress bar and ETA show during downloading.
  4. When the build completes, the chip becomes Loaded and the node count populates. Open Browse to query it.

You can leave the Inventories page during the build; updates resume the next time you visit. The build keeps running even if your browser tab closes.

§ 04 — Workflow

Browsing a prefix tree.

Browse is a directory-style explorer. Pick a loaded inventory and a starting prefix — empty means the bucket root. The page shows aggregated stats for that prefix and its immediate children.

  • Click a child prefix (📁) to drill in. The address bar updates so you can share or bookmark the URL.
  • Breadcrumbs at the top navigate back up; the rightmost one is the current location.
  • Storage tier breakdown is collapsible. When present it also shows a monthly cost estimate from US-East-1 prices (override with --price-table).
  • Sort columns by clicking the header — Segment, Objects, Size, or Est. Cost / mo.
  • Type a prefix + Enter to jump directly without drilling down step by step.

§ 06 — Reference

Action buttons.

Load
Submits a fresh build job. Cache directory is wiped before the pipeline runs; partial builds are never resumed.
Reload
Re-runs the build from scratch. Use when the upstream inventory has a newer run available.
Retry
Shown on error rows. Same as Load — wipes the partial cache and restarts the pipeline.
Unload
Releases the index from memory. The on-disk cache stays for a fast Reload later — no re-download required.
Cancel
Signals the in-flight build to stop. The pipeline winds down at its next safe checkpoint; the row flips to error with "context canceled" in the tooltip. Click Retry to start over.
§ 07 — How it works

Progress & ETA.

During a load, the row updates over a single Server-Sent Events connection the page opens with the server. Whenever the build pipeline moves stage or finishes a chunk, the row re-renders itself — no manual refresh.

  • Stage label tracks the pipeline: Preparing → Initializing → Downloading & parsing → Building index → Done.
  • Progress bar & "X/Y" show chunks of the inventory ingested out of the total declared in the manifest.
  • "~Xm Ys remaining" is a linear projection from elapsed time: elapsed × (total − done) / done. Less accurate at the very start, accurate by the time you've ingested a handful of chunks.
§ 08 — How it works

Persistence & restarts.

The server keeps a SQLite file at $CACHE_DIR/state.db with one row per inventory and one row per job. Every state change in memory mirrors itself into this file.

When the server restarts:

  • Loaded inventories are rehydrated by re-opening their on-disk index — your queries keep working without a rebuild.
  • Builds in flight at shutdown can't safely resume, so their inventories flip to Error with the message "interrupted by server restart". Click Retry.
  • Queued or running jobs from the previous process are stamped aborted in the job history.
§ 09 — Craft

Tips & shortcuts.

URLs are state
Copy the address bar at any point on Browse — another person opening it lands in the same prefix, with the same sort and page.
Back / forward
Navigation inside Browse — children, breadcrumbs, sort headers — is reflected in history. Back returns to the previous prefix; the inventory and prefix inputs always show the URL's actual values.
Dark mode
Toggle the sun / moon in the top-right of any page. Stored locally; applied before first paint, no flash on reload.
Keyboard
Tab walks every page in reading order; buttons accept Enter and Space. Browse child links are real <a> — middle-click or Ctrl-click opens in a new tab.
§ 10 — When things go sideways

Troubleshooting.

› A build is stuck and the ETA isn't moving.
Click Cancel. The pipeline winds down at its next safe checkpoint and the row flips to Error. Then click Retry. If the same inventory consistently hangs in the same stage, check the server logs — the manifest may point at unreachable objects.
› After a restart, my row shows "interrupted by server restart".
Expected. Mid-flight builds aren't safe to resume — the partial cache directory is invalid. Click Retry to rerun cleanly. Inventories fully loaded before the restart come back as Loaded automatically.
› The Inventories list is empty.
{{if .HasDiscovery}} The server is configured with {{.S3Source}} but no inventory configurations were found under that prefix. Make sure your S3 Inventory configuration is publishing reports there and at least one run has completed. {{else}} Discovery is disabled. Start the server with --s3-source s3://bucket/inventory-prefix/ to populate the list. {{end}}
› Browse says "select a loaded inventory" but I just loaded one.
The dropdown only lists inventories currently in the Loaded state. If yours is Loading…, wait for the build. If it's Unloaded or Error, click Reload / Retry first.
› I want to free disk space.
On-disk indexes live under $CACHE_DIR/<src-bucket>/<inv-id>/. Click Unload first, then remove the directory manually. The row returns to Not loaded on the next refresh; click Load again to rebuild.
§ 11 — Glossary

Terms in one line.

Inventory
One S3 Inventory configuration — a manifest describing every object in a source bucket at a point in time.
Run
One snapshot produced by an inventory configuration. S3 emits these on a schedule; the server uses only the latest.
Index
The mmap-backed on-disk artifact built from an inventory. Enables O(1) prefix lookups and fast subtree aggregation.
Prefix
A path inside the source bucket (e.g. data/2024/). Browse navigates the prefix tree.
Tier
The S3 storage class — Standard, Standard-IA, Glacier Instant, and so on. The tier breakdown shows how many objects + bytes live in each class.
Cost estimate
Monthly $ figure from the tier breakdown × a price table. Defaults to US-East-1; override with --price-table.
